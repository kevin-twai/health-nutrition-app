# Design Document

## Overview

本設計文件描述如何修復 EnhancedPromptGenerator 中的限制性 prompt 問題。核心問題是當前 prompt 過度強調 description 和 foods 列表的一致性，導致 AI 在生成結構化數據時受到約束，無法正確識別圖片中的所有食材。

修復策略：
1. 重新組織 prompt 的結構，將「識別所有食材」放在最優先位置
2. 移除或修改限制性語句，避免暗示 foods 列表必須與 description 一致
3. 強調 foods 列表是獨立的、完整的食材清單，不受 description 影響
4. 提供清晰的範例，展示如何識別多種食材

## Architecture

### 修改範圍

主要修改文件：
- `apps/api/src/services/EnhancedPromptGenerator.ts`

修改的方法：
1. `createAsianCuisineTemplate()` - 亞洲料理通用模板
2. `createSoupPrompt()` - 湯品識別模板
3. `createColdDishPrompt()` - 涼拌菜識別模板
4. `createMixedDishPrompt()` - 混合菜餚識別模板
5. 其他相關模板（如需要）

### 設計原則

1. **優先順序明確**：
   - 第一步：仔細觀察圖片，識別所有可見的食材
   - 第二步：估算每種食材的份量
   - 第三步：撰寫整體描述

2. **獨立性**：
   - foods 列表是獨立的結構化數據
   - description 是補充說明，不應限制 foods 列表

3. **完整性**：
   - 強調「所有可見食材」而不是「主要食材」
   - 提供檢查清單，確保不遺漏食材

4. **清晰性**：
   - 使用明確的指令（「必須」、「請列出」、「不要遺漏」）
   - 避免模糊的表述（「可以」、「如果提到」）

## Components and Interfaces

### 1. Prompt 結構重組

#### 當前結構（有問題）：
```
1. 角色定義
2. 識別重點
3. JSON 格式說明
4. 特別注意事項（包含限制性語句）
```

#### 新結構（修復後）：
```
1. 角色定義
2. **核心任務**：識別圖片中的所有食材（最優先）
3. 識別步驟：
   - 步驟 1：仔細觀察圖片
   - 步驟 2：識別每一種食材
   - 步驟 3：估算份量
   - 步驟 4：撰寫描述
4. JSON 格式說明
5. 食材識別重點
6. 範例（展示多種食材的識別）
7. 特別注意事項（強調完整性）
```

### 2. 關鍵修改點

#### 修改點 1：移除限制性語句

**當前（有問題）**：
```
**重要**：foods 列表必須包含所有可見的食材。如果你在 description 或 overallDescription 中提到了某個食材，那麼該食材也必須出現在 foods 列表中
```

**修改後**：
```
**重要**：
1. **優先任務**：仔細觀察圖片，識別並列出所有可見的食材到 foods 列表中
2. foods 列表是獨立的結構化數據，必須包含圖片中的所有食材
3. description 是對整體料理的補充說明，不應限制 foods 列表的內容
4. 即使某個食材在 description 中未提及，只要在圖片中可見，就必須加入 foods 列表
```

#### 修改點 2：添加識別步驟

```
## 識別步驟（請按順序執行）

### 步驟 1：仔細觀察圖片
- 從整體到細節觀察圖片
- 注意不同位置的食材（表面、中間、底部）
- 識別顏色、形狀、質地等視覺特徵

### 步驟 2：識別每一種食材
- 列出所有可見的食材，包括：
  * 主要食材（如肉類、主菜）
  * 配菜（如蔬菜、豆製品）
  * 小配料（如蔥花、香菜、芝麻）
  * 調味料（如醬汁、油）
- 不要遺漏任何可見的食材

### 步驟 3：估算份量
- 為每種食材估算合理的份量（公克或毫升）
- 參考常見份量標準

### 步驟 4：撰寫描述
- 在完成 foods 列表後，撰寫整體描述
- description 用於補充說明料理特色、烹飪方式等
```

#### 修改點 3：添加完整性檢查清單

```
## 完整性檢查清單

在提交回應前，請確認：
- [ ] 已識別所有可見的主要食材
- [ ] 已識別所有可見的配菜
- [ ] 已識別所有可見的小配料（蔥花、香菜等）
- [ ] 已識別調味料或醬汁
- [ ] foods 列表中至少有 3 種食材（如果圖片中有多種食材）
- [ ] 每種食材都有合理的份量估算
- [ ] 沒有遺漏任何明顯可見的食材
```

### 3. 特定料理類型的修改

#### 湯品 Prompt 修改

**當前問題**：
- 可能只識別湯底，忽略配料
- 沒有強調配料的重要性

**修改方案**：
```
## 湯品識別特別注意

**核心任務**：識別湯底和所有配料

### 必須識別的元素：
1. **湯底**（約 200-300ml）
   - 類型：清湯/濃湯/味噌湯/羹湯等
   - 顏色和濃稠度

2. **所有配料**（每種都要列出）
   - 蛋白質：豆腐、肉片、魚片、蛋等
   - 蔬菜：海帶、蔥花、香菇等
   - 其他：丸子、餃子、麵條等

### 識別步驟：
1. 先識別湯底類型和份量
2. 仔細觀察湯中的所有配料
3. 注意不同位置的配料：
   - 浮在表面的（蔥花、油）
   - 中間的（豆腐、肉片）
   - 沉在底部的（海帶、麵條）
4. 為每種配料估算份量

### 範例：
如果是味噌湯，foods 列表應包含：
- 味噌湯底（250ml）
- 豆腐（30g）
- 海帶芽（10g）
- 蔥花（5g）
- 其他可見配料

**不要只回應「味噌湯」，必須列出所有配料！**
```

#### 涼拌菜 Prompt 修改

**當前問題**：
- 可能只識別主要食材（如豆干）
- 忽略配菜（芹菜、胡蘿蔔等）

**修改方案**：
```
## 涼拌菜識別特別注意

**核心任務**：識別所有混合的食材

涼拌菜通常包含多種食材混合，請仔細識別每一種：

### 必須識別的元素：
1. **主食材**（通常 1-2 種）
   - 豆腐干絲、海蜇皮、木耳、黃瓜等

2. **配菜**（通常 2-4 種）
   - 芹菜絲、胡蘿蔔絲、香菜、蔥絲等

3. **調味料**
   - 麻油、醬油、醋、蒜末、薑絲等

### 識別技巧：
- 注意不同顏色的食材（綠色、橙色、白色、黃色）
- 注意不同形狀的食材（絲狀、片狀、塊狀）
- 涼拌菜通常有 3-6 種食材，如果只識別到 1-2 種，請再仔細觀察

### 範例：
涼拌干絲的 foods 列表應包含：
- 豆腐干絲（80g）
- 芹菜絲（20g）
- 胡蘿蔔絲（15g）
- 香菜（5g）
- 麻油（5ml）
- 醬油（10ml）

**不要只回應「豆腐干絲」，必須列出所有可見的食材！**
```

## Data Models

### Prompt Template 結構

```typescript
interface PromptTemplate {
  // 角色定義
  role: string;
  
  // 核心任務（新增）
  coreTask: string;
  
  // 識別步驟（新增）
  identificationSteps: string[];
  
  // 識別重點
  identificationFocus: string[];
  
  // JSON 格式說明
  jsonFormat: string;
  
  // 範例（新增/增強）
  examples: string[];
  
  // 完整性檢查清單（新增）
  completenessChecklist: string[];
  
  // 特別注意事項
  specialNotes: string[];
}
```

### 修改後的 JSON 回應格式

保持現有格式不變，但在 prompt 中強調：

```json
{
  "foods": [
    {
      "name": "食材名稱",
      "confidence": 0.95,
      "portion": 50,
      "category": "類別",
      "description": "描述"
    }
  ],
  "overallDescription": "整體描述（補充說明，不限制 foods 列表）"
}
```

## Error Handling

### 潛在問題和解決方案

1. **問題**：AI 仍然只識別少數食材
   **解決**：在 prompt 中添加最小食材數量要求
   ```
   如果圖片中明顯有多種食材（如涼拌菜、湯品、便當），foods 列表應至少包含 3-5 種食材
   ```

2. **問題**：AI 識別了不存在的食材
   **解決**：強調「只識別可見的食材」
   ```
   只識別圖片中明確可見的食材，不要推測或添加圖片中沒有的食材
   ```

3. **問題**：份量估算不準確
   **解決**：提供份量參考標準
   ```
   份量估算參考：
   - 豆腐：每塊約 30-50g
   - 蔬菜絲：每份約 20-30g
   - 蔥花：約 5-10g
   - 湯底：約 200-300ml
   ```

## Testing Strategy

### 測試方法

1. **單元測試**：
   - 測試 prompt 生成是否包含新的結構元素
   - 測試是否移除了限制性語句

2. **整合測試**：
   - 使用真實圖片測試識別結果
   - 比較修復前後的 foods 列表長度

3. **測試案例**：

#### 測試案例 1：味噌湯
- **輸入**：味噌湯圖片（包含豆腐、海帶、蔥花）
- **預期輸出**：
  ```json
  {
    "foods": [
      {"name": "味噌湯底", "portion": 250},
      {"name": "豆腐", "portion": 30},
      {"name": "海帶芽", "portion": 10},
      {"name": "蔥花", "portion": 5}
    ]
  }
  ```
- **成功標準**：foods 列表包含至少 3 種食材

#### 測試案例 2：涼拌干絲
- **輸入**：涼拌干絲圖片（包含豆干、芹菜、胡蘿蔔、香菜）
- **預期輸出**：
  ```json
  {
    "foods": [
      {"name": "豆腐干絲", "portion": 80},
      {"name": "芹菜絲", "portion": 20},
      {"name": "胡蘿蔔絲", "portion": 15},
      {"name": "香菜", "portion": 5},
      {"name": "麻油", "portion": 5}
    ]
  }
  ```
- **成功標準**：foods 列表包含至少 4 種食材

#### 測試案例 3：台式熱炒
- **輸入**：炒豆干圖片（包含豆干、糯米椒、蒜片、辣椒）
- **預期輸出**：
  ```json
  {
    "foods": [
      {"name": "豆干", "portion": 100},
      {"name": "糯米椒", "portion": 50},
      {"name": "蒜片", "portion": 10},
      {"name": "辣椒", "portion": 5}
    ]
  }
  ```
- **成功標準**：foods 列表包含至少 3 種食材

### 驗證指標

1. **食材識別完整度**：
   - 目標：識別出至少 80% 的可見食材
   - 計算方式：(識別出的食材數 / 實際可見食材數) × 100%

2. **foods 列表長度**：
   - 修復前：平均 1-2 種食材
   - 修復後：平均 3-5 種食材（複雜料理）

3. **準確度**：
   - 目標：識別出的食材中，至少 90% 是正確的
   - 計算方式：(正確識別的食材數 / 總識別食材數) × 100%

## Implementation Notes

### 修改優先順序

1. **高優先級**（必須修改）：
   - `createAsianCuisineTemplate()` - 影響所有亞洲料理識別
   - `createSoupPrompt()` - 湯品識別問題最明顯
   - `createColdDishPrompt()` - 涼拌菜識別問題明顯

2. **中優先級**（建議修改）：
   - `createMixedDishPrompt()` - 混合菜餚識別
   - `createStirFryPrompt()` - 熱炒識別
   - `createTaiwanesePrompt()` - 台式料理識別

3. **低優先級**（可選修改）：
   - 其他特定料理類型的 prompt

### 向後兼容性

- 修改不會影響現有的 API 接口
- JSON 回應格式保持不變
- 只是改善 prompt 的內容和結構

### 部署策略

1. 先在測試環境部署
2. 使用測試圖片驗證效果
3. 比較修復前後的識別結果
4. 確認無問題後部署到生產環境

## Summary

本設計通過重組 prompt 結構、移除限制性語句、添加識別步驟和完整性檢查清單，來解決當前 AI 無法正確識別所有食材的問題。核心改變是將「識別所有食材」作為最優先任務，並明確說明 foods 列表是獨立的結構化數據，不受 description 內容的限制。

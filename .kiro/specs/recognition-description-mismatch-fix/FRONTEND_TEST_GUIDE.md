# 前端測試指南 - 識別一致性修復

## 測試目的

驗證前端上傳照片後，基礎識別和成分檢測返回一致的食物列表。

- **本地開發**: http://localhost:3000

## 測試步驟

### 1. 啟動前端開發服務器

```bash
cd apps/web
npm run dev
```

前端會在 http://localhost:3000 啟動。

### 2. 訪問照片識別頁面

打開瀏覽器訪問：
```
http://localhost:3000/photo
```

### 3. 上傳測試照片

#### 測試照片建議
- **便當照片**: 包含多個食物項目（白飯、主菜、配菜）
- **湯麵照片**: 包含麵條、湯底、配料
- **咖喱照片**: 包含咖喱、米飯、蔬菜
- **單一食物**: 測試簡單場景

#### 上傳步驟
1. 點擊「選擇照片」或拖放照片
2. 選擇測試照片
3. 點擊「🔍 開始分析」按鈕

### 4. 觀察處理過程

#### 瀏覽器控制台日誌

打開瀏覽器開發者工具（F12），查看 Console 標籤：

```

```

#### 預期日誌內容

```javascript

  - success: true

  - suggestions: [...]

```

### 5. 驗證結果一致性

#### 檢查項目

1. **主料理信息**
   - 顯示料理名稱
   - 顯示料理類型和烹飪方式
   - 顯示檢測到的成分數量

2. **成分列表**
   - 每個成分都有名稱、類別、份量
   - 每個成分都有營養資訊（卡路里、蛋白質、碳水、脂肪）
   - 信心度顯示正常

3. **營養總計**
   - 總卡路里
   - 總蛋白質
   - 總碳水化合物
   - 總脂肪

#### 一致性驗證

**關鍵檢查**：基礎識別的食物列表應該與成分檢測的成分列表一致。

在控制台查看：
```javascript
// 基礎識別結果
recognition.foods: [
  { name: "白飯", ... },
  { name: "炸豬排", ... },
  { name: "滷蛋", ... }
]

// 成分檢測結果
componentDetection.components: [
  { name: "白飯", ... },
  { name: "炸豬排", ... },
  { name: "滷蛋", ... }
]
```

**✅ 通過條件**：兩個列表的食物名稱應該完全一致。

## 常見問題

### Q1: 前端顯示「無法連接到後端服務器」

**解決方案**:
1. 檢查後端 API 是否運行
2. 訪問 https://health-nutrition-api.onrender.com/health
3. 確認返回 `{"status":"ok"}`

### Q2: 成分識別結果為空

**可能原因**:
- 後端未正確傳遞預識別食物
- ComponentDetectionEngine 降級到 Vision API

**檢查**:
```javascript
// 控制台應該顯示
componentDetection.metadata.detectionMethod: "pre_recognized"
componentDetection.metadata.componentsFromPreRecognition: > 0
```

### Q3: 一致性警告

**可能原因**:
- 某些食物在轉換過程中丟失
- 類別推斷失敗

**檢查**:
```javascript
// 控制台會顯示
⚠️ 一致性警告: 以下食物在成分列表中缺失: [...]
```
